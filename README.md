# Beer Style Assistant

Telegram-бот — справочник по пивным стилям [BJCP 2021](https://www.bjcp.org/) на основе RAG.
Учебный проект: вопрос → поиск подходящих стилей в базе → ответ языковой модели только по найденным данным.

## Как это работает

```
Telegram ─► bot.py ─► RAGPipeline
                        ├─ Embedder      OpenAI text-embedding-3-small
                        ├─ VectorStore   FAISS, косинусная близость
                        └─ LLM           GigaChat (OAuth + /chat/completions)
```

- **Индексация** (`/ingest` или `scripts/ingest.py`): `data/styles/*.md` режутся по стилям
  (один стиль = один чанк), эмбеддинги считает OpenAI, индекс лежит в `data/index/`.
- **Вопрос.** Сначала GigaChat разбирает его в JSON: это справка или сравнение, и (по-английски)
  что искать. Дальше два пути:
  - **Справка** («какая горечь у IPA?»): эмбеддинг вопроса → top-4 стиля → если лучшее совпадение
    ниже порога `MIN_SCORE`, бот говорит «в базе нет» → иначе контекст уходит в GigaChat.
    Числа в ответе проверяются кодом: если есть число, которого нет в найденных стилях, модель
    один раз просят исправить ответ; если ошибка осталась, ответ отдаётся, а админ видит
    «⚠ числа не из контекста» в отладочной строке.
  - **Сравнение** («чем отличается портер от стаута?»): группа — это **все** стили BJCP, в названии
    которых есть ключевое слово (`stout` → 8 стилей), а не «топ-N по похожести». Диапазоны IBU/SRM/ABV
    и среднее (среднее середин диапазонов) **считает код**, модель чисел не видит и не пишет.
    Ответ — компактная сводка чисел и названий стилей, без описаний и выводов. Если стороны нет
    в базе, бот так и говорит; если ключ не совпал с названиями (алиас вроде «weizen»), стили
    подбираются по смыслу и это помечается в ответе (порог `GROUP_FALLBACK_MIN_SCORE`).
    Необязательная характеристика групп от модели включается `COMPARE_TRAITS=on`, по умолчанию
    выключена: в замерах она путала перевод и жанры.
- **Эмбеддинги и генерация — независимые модели.** Но документы и запросы обязаны
  кодироваться одной эмбеддинг-моделью: имя модели хранится в индексе, при несовпадении
  бот просит переиндексацию. Модель генерации можно менять без переиндексации.
- База знаний на английском, ответы бот переводит на русский на лету.

## Установка

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env     # и впишите ключи
```

Сертификат Минцифры для GigaChat: клиент использует хранилище сертификатов ОС
(пакет `truststore`). Если корневого сертификата там нет, укажите путь к PEM
в `GIGACHAT_CA_BUNDLE`. Отключать проверку TLS не нужно.

## Запуск

```bash
.venv/bin/python scripts/fetch_bjcp.py   # скачать базу BJCP (один раз)
.venv/bin/python scripts/ingest.py       # проиндексировать
.venv/bin/python scripts/try_query.py --retrieval-only "Какая горечь у American IPA?"
.venv/bin/python bot.py
```

`scripts/try_query.py` показывает score найденных стилей — по нему подбирается `MIN_SCORE`.

## Источники и отладка

Под ответом бот может показывать источники (какие стили нашёл) и служебную строку
(`score`, токены). Это инструмент отладки, обычным пользователям он не нужен. Режим задаётся в
`.env`: `SHOW_SOURCES=admin` (по умолчанию: видят только админы), `off` (никто) или `all`.
Для реальных пользователей оставляй `admin` или `off`.

## Как пользоваться

**Обычный пользователь** команд знать не должен: меню команд у него пустое. Он просто пишет
вопрос текстом. На «привет», «что ты умеешь?», «как тобой пользоваться» бот отвечает сам
(без обращения к модели, то есть бесплатно), а фраза «начнём заново» (или «забудь всё»)
сбрасывает контекст разговора. Технически это те же команды `/start`, `/help`, `/clear`,
их можно набрать вручную. Дополнительно есть `/ask вопрос`, `/stats` и `/myid`.

**Администратор** (`ADMIN_IDS`) видит меню команд «/» (только в его чате). Команда, которой
нужен аргумент, спрашивает его отдельным сообщением, а следующее сообщение админа считается
ответом; любая другая команда, `/cancel` или 5 минут тишины отменяют ожидание.

| Команда | Что делает |
|---|---|
| `/invite` | Создаёт инвайт (один инвайт — один человек, 7 дней). Бот присылает служебное сообщение и отдельное готовое приглашение со ссылкой для пересылки. Необязательно: `/invite 14 Маша` (срок и заметка) |
| `/users` | Карточка на каждого пользователя с кнопками «Кто это» (ник и имя запрашиваются у Telegram и не хранятся), «Заметка», «Заблокировать/Разблокировать» |
| `/invites` | Действующие инвайты с кнопкой «Отозвать» и общей «Отозвать все» |
| `/whois`, `/note`, `/kick`, `/unblock`, `/revoke` | То же командами: без аргумента бот спросит его, с аргументом выполнит сразу (`/kick 123456789`) |
| `/cancel` | Отменить ожидание аргумента |
| `/ingest` | Переиндексация базы знаний |

Демонстрация интерфейса без Telegram и ключей: `python tests/demo_transcript.py`
печатает переписку с кнопками, прогнанную через настоящий код бота.

## Доступ по инвайтам

Бот отвечает только администраторам (`ADMIN_IDS`, обязателен) и тем, кто погасил инвайт.
Остальным приходит одна фраза «работает по приглашениям», при этом OpenAI и GigaChat
не вызываются, то есть чужие запросы не тратят токены.

- Один инвайт — один вход одного пользователя; живёт 7 дней (срок задаётся в `/invite`).
- Погашение идёт в транзакции `BEGIN IMMEDIATE`: даже два процесса (например, старый и новый
  экземпляр бота при рестарте) не могут погасить один код дважды или создать дубль пользователя.
- Пользователю при любой неудаче показывается один и тот же текст. Причина (`not_found`,
  `used_up`, `expired`, `revoked`, `blocked`) уходит в лог и админу: по ней видно перебор кодов
  и пересылку ссылок.
- Пять неверных кодов за час — бот перестаёт отвечать этому пользователю.
- `/kick` блокирует, а не удаляет: заблокированный не войдёт и по новому инвайту, пока не
  сделаешь `/unblock`; при такой попытке инвайт не сгорает, его можно отдать другому.
- Уже участник, открывший чужую или свою ссылку, инвайт не тратит (админу удобно проверять
  собственные ссылки; от «вечных» ссылок защищают срок жизни и лимит использований).
- Админ получает уведомление о новых пользователях и о неудачных попытках входа.
- **О человеке хранится только Telegram ID**, время входа и заметка, которую написал админ.
  Ники и имена в базу и в лог не пишутся; узнать их можно командой `/whois ID` (Telegram
  отдаёт их по ID тем, кто писал боту). Заметка нужна на случай, если человек скрыл ник.
- Список хранится в `data/access.db` (SQLite, в git не попадает); на VPS его нужно
  сохранять между выкладками, иначе пользователям придётся выдавать инвайты заново.
  Схема мигрирует автоматически при старте.
- Тесты (`tests/harness.py` подменяет Telegram, остальное настоящее):
  `test_access.py` (хранилище), `test_bot_access.py` (сценарии бота: доступ, меню, ожидание
  аргументов, кнопки), `test_smalltalk.py`, `test_invite_race.py` (20 процессов на один код).

## Планы: лимиты токенов на пользователя

Заготовка есть: `Answer.tokens` — сколько токенов GigaChat потратил на запрос
(переписывание запроса + ответ; типичный вопрос ≈ 3 000 на модели Lite). Сейчас число пишется
в лог. Когда понадобятся лимиты: таблица `usage(user_id, day, tokens)` в `data/access.db`,
проверка перед `pipeline.answer()` и запись после (место отмечено комментарием в `bot.py:ask`),
лимит и исключение для админов — в `.env`. Токены эмбеддингов OpenAI не учитываются:
запрос стоит сотые доли цента.

## Структура

```
bot.py            Telegram-хендлеры, меню, кнопки
access.py         инвайты и список пользователей (SQLite)
smalltalk.py      ответы на «привет», «что ты умеешь?», «начнём заново» без LLM
config.py         настройки и промпты
rag/              embedder, vectorstore, loader, pipeline, compare (сравнение), verify (проверка чисел)
llm/gigachat.py   клиент GigaChat
scripts/          fetch_bjcp, ingest, try_query
tests/            тесты и демо переписки
data/styles/      база знаний (markdown)
```

## Деплой на VPS

Бот рассчитан на запуск на отдельном сервере (процесс под systemd или в контейнере).

- Зависимости: `requirements.lock` — проверенные версии (`pip install -r requirements.lock`).
- Секреты только через `.env` (права 600) или переменные окружения; в git их нет.
- Индекс `data/index/` в git не хранится: после выкладки выполнить `python scripts/ingest.py`
  (нужен `OPENAI_API_KEY`) и только потом стартовать бота.
- Корневой сертификат Минцифры должен быть в хранилище ОС сервера
  (или указан в `GIGACHAT_CA_BUNDLE`), иначе GigaChat недоступен.
- Логи пишутся в `bot.log` и stdout; бот работает через long polling, входящие порты не нужны.
- Бесплатный тариф GigaChat однопоточный: запросы к модели сериализуются внутри процесса,
  запускать больше одного экземпляра бота нельзя.
