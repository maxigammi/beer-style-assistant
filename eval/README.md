# eval: проверка качества поиска и ответов

Инструменты, которыми проверялось качество бота. В боевой код и в образ бота они не входят: у них свои зависимости (RAGAS) и свой запуск.

| Файл | Что делает |
|---|---|
| `questions.py` | 5 тестовых вопросов с эталонными ответами и требованиями к поиску (`must`, `must_any_titles`) |
| `retrieval_check.py` | быстрая проверка только поиска: нашлись ли обязательные стили. Без RAGAS и без судьи, секунды |
| `rag_assistant.py` | тот же пайплайн, что у бота, но с выводом найденных стилей, score и предупреждений проверки выдумки (код бота не меняется) |
| `evaluate_rag.py` | RAGAS: faithfulness, answer_relevancy, context_precision, context_recall; судья `gpt-4o-mini` |
| `ingest.py` | обёртка над `scripts/ingest.py` |
| `results/` | сырые результаты прогонов RAGAS (JSON) |

## Запуск

Нужны ключи в `.env` в корне проекта (как для бота) и собранный индекс (`python scripts/ingest.py`).

Проверка поиска (хватает окружения самого бота):

```bash
python eval/retrieval_check.py            # top_k как в боте
python eval/retrieval_check.py --top-k 3
```

Один вопрос с признаками качества:

```bash
python eval/rag_assistant.py "Какая горечь у American IPA?"
```

RAGAS: отдельное окружение на Python 3.12 (зависимости RAGAS не собираются на 3.14 и понижают версию `openai`, поэтому окружение бота не трогаем):

```bash
uv venv --python 3.12 eval/.venv-eval
uv pip install --python eval/.venv-eval/bin/python -r eval/requirements-eval.txt
eval/.venv-eval/bin/python eval/evaluate_rag.py --runs 3             # top_k как в боте (6)
eval/.venv-eval/bin/python eval/evaluate_rag.py --top-k 3 --runs 3
```

## Что проверяется

- Q1-Q3: нужный стиль обязан быть в выдаче (`must`: коды 13C, 3B, 24A).
- Q4 (кофе и шоколад): подходят около 30 стилей из 123, поэтому проверяется семейство, а не конкретный код: хотя бы один стаут и хотя бы один портер (`must_any_titles`, группировка по названию как в режиме сравнения бота).
- Q5 (калории Guinness): ответа в базе нет. RAGAS оценивает такой отказ нулями, поэтому отказ проверяется отдельно: в ответе есть отказ и нет ни одной цифры.

## Результаты

Эталоны составлены вручную по тексту `data/styles` (вместе с Claude Code), без независимого эксперта. Пять вопросов это очень мало: цифры показывают направление, а не точную оценку.

RAGAS 0.4.3, судья `gpt-4o-mini`, 3 прогона на конфигурацию (24.09.2026), средние по вопросам с ответом в базе (без Q5), в скобках разброс между прогонами:

| Метрика | top_k=6 (как в боте) | top_k=3 |
|---|---|---|
| faithfulness | 0.86 (0.82-0.90) | 0.96 (0.91-1.00) |
| answer_relevancy | 0.86 | 0.88 |
| context_precision | 0.85 | 0.85 |
| context_recall | 0.80 | 0.77 |

Вывод: разница на грани шума, `top_k=3` не принят. Из-за лимита контекста 12000 символов в запрос к модели попадает 3-4 стиля, поэтому `top_k` почти ничего не меняет.

Проверка отказа на вопрос без ответа (Q5): 6 из 6 прогонов.

Проверка поиска (`retrieval_check.py`): 5 из 5 на 29.09.2026 и повторно на 15.10.2026. До правок поиска (перевод запроса без исходного русского текста, правила про вкус в `UNDERSTAND_PROMPT`) вопрос Q4 не проходил, было 4 из 5. Один дополнительный прогон RAGAS после первой правки: `results/run_top6_20260929_143122.json`.

## Ограничения

- `answer_relevancy` считалась по одной сгенерированной перефразировке вопроса вместо трёх (ограничение обёртки между langchain и RAGAS), поэтому она шумнее, чем в справочной настройке.
- Эмбеддинги этой метрики (`text-embedding-3-small`) те же, которыми бот ищет ответы: проверка не полностью независима от проверяемой системы.
- Судья сверяет русские ответы с английским контекстом, часть замечаний к faithfulness может быть следствием перевода, а не выдумки.
- Режимы «сравнение» и «семейство» метриками RAGAS не измерялись: они считаются кодом без участия модели.
- `context_recall` добавлена сверх исходного задания, чтобы увидеть неполные ответы (на Q4 она показывала 0.20).
