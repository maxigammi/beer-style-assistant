## 1. Цель, пользователь, ценность

**Цель.** Быстро и без выдумок отвечать на вопросы о пивных стилях, опираясь только на руководство BJCP 2021 (123 стиля).

**Пользователь.** Любитель пива, начинающий пивовар или судья, который хочет получить справку по стилю («какая горечь у American IPA?»), сравнить стили («чем портер отличается от стаута?») или посмотреть, какие бывают стили в семействе («расскажи про лагеры»). Пишет обычным текстом по-русски, команд знать не нужно.

**Ключевая ценность.**
- Ответ основан только на тексте руководства. Числа (IBU, SRM, ABV и т. д.) передаются точно; если в базе чего-то нет, бот говорит об этом прямо.
- Сравнение стилей считает код, а не модель: диапазоны и средние значения не выдумываются.
- Чужие запросы не тратят деньги: бот отвечает только администраторам и тем, кто вошёл по приглашению.

**Чего бот не делает намеренно:** не называет конкретные марки пива, цены, места покупки, сочетания с едой и рецепты (этого нет в руководстве); в таких случаях отвечает, что в базе знаний этой информации нет.

## 2. Как это устроено

```
Telegram ─► bot.py ─► RAGPipeline
                        1. Разбор вопроса (языковая модель): справка | сравнение | семейство
                        2a. Справка:   поиск по смыслу (эмбеддинги + FAISS) → ответ модели строго по найденному
                                       → проверка кодом (числа и английские названия должны быть в контексте)
                        2b. Сравнение: группы стилей по названию, числа и среднее считает код
                        2c. Семейство: список стилей без обращения к модели
```

| Компонент | Что используется | Зачем |
|---|---|---|
| Бот | Python, aiogram | приём сообщений, меню, кнопки администратора |
| Генерация | GigaChat (`GigaChat-2-Pro`) | разбор вопроса и формулировка ответа |
| Эмбеддинги | OpenAI `text-embedding-3-small` | поиск по смыслу |
| Индекс | FAISS, косинусная близость, 123 фрагмента (один стиль = один фрагмент) | хранение векторов |
| Доступ | SQLite (`access.db`): инвайты и список пользователей | кто может пользоваться ботом |
| Кэш | в памяти процесса, по точному совпадению вопроса (регистр и пунктуация не важны), только когда нет истории диалога | повторный вопрос отдаётся без обращения к моделям |

Эмбеддинги и генерация — независимые модели: смена модели ответов не требует переиндексации, смена модели эмбеддингов требует.

**Данные.** База знаний — тексты BJCP 2021 на английском (папка `data/styles`, 34 файла); бот переводит ответы на русский на лету. База скачана один раз, регулярного обновления нет.

**Роли.** Администраторы (список `ADMIN_IDS`) создают инвайты, видят пользователей, запускают переиндексацию и видят служебную строку под ответом (найденные стили, оценка поиска, токены). Обычные пользователи входят по одноразовому приглашению (живёт 7 дней).

## 3. Быстрый запуск (локально)

```
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env                       # вписать ключи
.venv/bin/python scripts/fetch_bjcp.py     # скачать базу (один раз)
.venv/bin/python scripts/ingest.py         # проиндексировать
.venv/bin/python scripts/preflight.py      # проверить окружение и доступ к сервисам
.venv/bin/python bot.py
```

Демонстрация интерфейса без Telegram и ключей: `python tests/demo_transcript.py`.

## 4. Конфигурация и секреты

Все настройки читаются из `.env` (шаблон `.env.example`, файл в git не попадает). Значения секретов в документацию не записываются.

| Переменная | Назначение | Где взять значение |
|---|---|---|
| `TELEGRAM_TOKEN` | токен бота | владелец, `@BotFather`; перевыпуск: команда `/revoke` в чате с `@BotFather` (не путать с командой бота `/revoke`, которая отзывает инвайты) |
| `ADMIN_IDS` | Telegram ID администраторов (обязательно) | команда бота `/myid` |
| `OPENAI_API_KEY` | эмбеддинги | кабинет OpenAI (владелец) |
| `GIGACHAT_AUTH_KEY` | генерация ответов | личный кабинет GigaChat (владелец) |
| `SHOW_SOURCES` | кому показывать служебную строку (`admin` по умолчанию) | — |
| `MIN_SCORE`, `GIGACHAT_MAX_WAIT_SEC`, `STATE_DIR`, `LOG_FILE`, `COMPARE_TRAITS` | необязательные настройки | описаны в `.env.example` |

При передаче проекта секреты не пересылаются файлом: новый сопровождающий получает собственные ключи или доступ через менеджер паролей владельца, а прежние ключи перевыпускаются.
